# Project Claudette

Claudette Marie Duvall is an **AI persona** that replies to Instagram DMs in real time. She is publicly known as an AI but operates fully in character — an 18-year-old recent high-school graduate from Burlington, Vermont — and remembers the people she talks to across sessions through a **dual-layer memory system** (short-term conversation history + long-term semantic vector memory). The backend is Node.js/Express, memory lives in Supabase (Postgres + pgvector), and replies are generated by Anthropic's `claude-sonnet-4-6`.

---

## Architecture at a glance

```
Instagram DM ─▶ Meta webhook ─▶ Express (/webhook/instagram)
                                   │
                                   ├─ guardrails/screener.js     (block injection/jailbreaks)
                                   ├─ utils/users.js             (upsert user)
                                   ├─ memory/ephemeral.js        (save + fetch recent messages)
                                   ├─ memory/retrieval.js        (semantic recall → memory block)
                                   ├─ llm/claudette.js           (claude-sonnet-4-6 reply)
                                   ├─ instagram/messenger.js     (send DM via Graph API)
                                   └─ memory/consolidation.js    (periodic long-term summaries)
```

## Prerequisites

- **Node.js 18+**
- A **Supabase** project (Postgres with the `pgvector` extension)
- A **Meta Developer App** with Instagram messaging + a Page/Instagram access token
- An **Anthropic API key** (for `claude-sonnet-4-6`)
- An **OpenAI API key** (for `text-embedding-3-small` embeddings)

### Environment variables

| Key | Purpose |
|---|---|
| `ANTHROPIC_API_KEY` | Auth for the Claude LLM engine |
| `META_VERIFY_TOKEN` | Arbitrary string you also paste into Meta's webhook config |
| `META_PAGE_ACCESS_TOKEN` | Bearer token used to send DMs via the Graph API |
| `INSTAGRAM_ACCOUNT_ID` | The connected Instagram account id |
| `SUPABASE_URL` | Your Supabase project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | Service-role key (server-side only — never ship to a browser) |
| `OPENAI_API_KEY` | Auth for `text-embedding-3-small` embeddings |
| `REDIS_URL` | Optional; the app uses Supabase for ephemeral memory by default |
| `PORT` | HTTP port (defaults to `3000`) |

### Supabase migration

Apply `supabase/migrations/001_init.sql`. Either:

- **Supabase SQL editor** — paste the file contents and run, or
- **Supabase CLI** — `supabase db push` (with the migration in place).

This creates the `users`, `messages`, and `memories` tables, enables `pgvector`, adds an IVFFlat index for cosine search, and installs the `match_memories(...)` function used for per-user semantic recall.

## Meta webhook setup

1. Deploy the backend so it has a public HTTPS URL (e.g. on Render — see below).
2. In your Meta App → **Webhooks** (Instagram product), add a callback:
   - **Callback URL:** `https://<your-host>/webhook/instagram`
   - **Verify Token:** the exact value you set for `META_VERIFY_TOKEN`
3. Meta sends a `GET` to that URL with `hub.mode`, `hub.verify_token`, and `hub.challenge`. The handler validates the token and echoes the challenge — verification succeeds automatically.
4. Subscribe to the **`messages`** field so incoming DMs are delivered as `POST` events.
5. Ensure your `META_PAGE_ACCESS_TOKEN` has the permissions required to read and send Instagram messages.

The `POST /webhook/instagram` handler ACKs with `200` immediately (Meta requires a fast response) and processes each message asynchronously.

## How the memory system works

**Ephemeral (short-term).** Every inbound and outbound message is written to the `messages` table. Before each reply, the last 15 messages are fetched in chronological order and passed straight to Claude as the conversation history. This is the "what we were just talking about" layer.

**Semantic (long-term).** Periodically (every 20 messages, or at session end), `consolidation.js` summarizes the recent exchange into a 2–3 sentence memory note from Claudette's perspective, embeds it with `text-embedding-3-small`, and stores it in the `memories` table. On each new message, `retrieval.js` embeds the incoming text and runs a cosine-similarity search (`match_memories`) scoped to that user, then injects the top matches into the system prompt as a hidden memory block. This is the "things she remembers about you" layer that lets her bring up past details naturally.

Together they give Claudette continuity: recent context plus durable, searchable long-term recall — per user, isolated by `user_id`.

## Deployment to Render

1. Push this repo to GitHub.
2. In Render, create a **Web Service** from the repo.
   - **Build command:** `npm install`
   - **Start command:** `npm start`
   - **Environment:** Node
3. Add every variable from the table above under the service's **Environment** settings.
4. Deploy. Render gives you a public HTTPS URL — use `https://<service>.onrender.com/webhook/instagram` as your Meta callback URL.
5. Confirm `GET /health` returns `{ "status": "ok", "persona": "Claudette" }`.
